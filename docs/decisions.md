# 決定事項と検討事項

この文書は、会話で確認した最新の結論と未決定事項を項目別にまとめたもの。機能の希望や方向性は、初期版にすべて含める決定ではない。具体的な要件は [企画・要件](product.md)、用語は [用語集](glossary.md)、初期版の分割案は [初期版・運用の提案](release-plan.md) を参照。

## 最新の決定・方向性

### 対象・公開

- 友人同士で使う。日記帳は２人から最大10人までで、複数作成できる。
- 一般公開を目指し、初期は無料。まず iOS、その後 Android、将来的にパソコン版も検討する。
- 運用費の上限は未定。問い合わせ対応は本人が担当する。

### アカウント・招待・閲覧

- アカウント作成は複数の方法を組み合わせる。具体的な方法は未決定。
- 招待リンクは24時間有効で、参加が１回成立すると使用できなくなる。リンクの作成者は無効化・再発行できる。既存参加者の承認は不要。発行時に、転送先も参加でき過去のページを読めることを伝え、参加時は既存参加者に通知する。参加時に10人の上限を確認する。転送先が先に使った場合の参加は防げない。
- 途中参加を認め、途中参加者も参加前のページを読める。

### 順番・周・スキップ

- 最初の順番は参加順。参加者なら誰でも順番を変更できる。現在の担当者は変わらない。その周の残りの順番を変更できるのは、まだ担当していない人同士。担当済みの人を含む変更は次の周に反映する。
- 周の開始時に対象者を決め、対象者がそれぞれ書くかスキップすると周が完了する。途中参加者は現在の周の対象に加えず、次の周の最後に入り、その後は順番を変更できる。
- まだ担当していない人が退出・ブロックされたら、その周の対象から外す。残る対象者が全員完了していれば周は終了。現在の担当者が退出・ブロックされた場合は次の未完了者へ進み、残りがいなければ周を終えて次の周に進む。
- 書く期限は設けず、本人だけが自分の番をスキップできる。スキップ時は履歴を残し、下書きを削除して次の人に進む。
- 次の人以外を指定して、自分の番を直接渡す機能は設けない。完成したページは順番の次の人に渡す。

### ページ・下書き・装飾

- フォーム型を独立した形式としては設けず、入力欄があらかじめ用意されたテンプレートも自由配置のページとして扱う方向。利用者は用意された欄に直接テキストを入力でき、空欄も許す。テンプレートは全体で８種類程度を目指すが、数や内容は試作後に見直す。
- ページのデコレーションを体験の中心にする。プリクラのデコ機能のように、豊富なペンや文字・柄スタンプで楽しく飾りたい。文字の直接入力も引き続きできるようにする。具体的な種類や操作は試作して検討する。
- 写真は１ページ５枚までで、端末の写真アプリから選ぶ。
- 下書きは本人だけが見られ、自動保存し、別端末でも続きを書ける。複数端末では後から保存された内容を優先する。
- 渡す前にプレビューを見せ、渡した後は編集できない旨を注釈で伝える。渡したページの編集は初期版に含めない。将来の編集機能は未決定。
- 渡したページは書いた本人が削除でき、付いているコメント・リアクションも削除する。非表示機能は設けない。

### リアクション・コメント・通知

- 事前に用意された固定の種類のリアクションを付けられ、１人が複数種類を付けられる。自分が付けたリアクションは取り消せる。初期版は固定セットに加え、iPhone の絵文字キーボードから好きな絵文字も選べる方針。絵文字の扱いの詳細や取り消しの単位などは未決定。
- コメントは短いものとし、編集できない。書いた本人が削除できる。文字数上限は未決定。
- 通知は各種用意し、種類別にオフにできるようにする。過去ページは時系列のほか、日付や書いた人で探せるようにしたい。

### 退出・ブロック

- 参加者はいつでも退出できる。他の参加者の強制退出は、ブロック時を除き設けない。現在の担当者が退出した場合は次の人の番になり、最後の１人が退出したら日記帳を自動削除する。
- 退出者が書いたページ・コメントは削除する。削除されるページに付いた他の参加者のコメント・リアクションも削除する。退出後は本人も日記帳を読めない。
- 参加者をブロックすると、対象者は操作された日記帳から退出する。その日記帳内で本人が書いたページ・コメント・付けたリアクションを削除する。ページに付いた他者のコメント・リアクションも削除する。削除は参加者全員に反映し、他の日記帳は対象外。
- ブロックされた人が現在の担当者なら次の人に番を渡す。通報を受け、運営者が確認して必要に応じアカウントを停止する案を検討する。審査適合性は未確認。

### 日記帳の削除

- 参加者なら誰でも削除を提案できるが、実行には参加者全員の同意が必要。未回答者がいる間は待つ。削除待ちの間に途中参加した人の同意も必要。
- 各参加者は削除実行前なら自分の同意を取り消せる。削除後は利用者が元に戻せない。バックアップからの削除・復元時の再反映方法は公開前に決める。

### デザイン

- 若い人が楽しめる、明るくデコレーション感のあるアプリ UI を目指す。特定の雰囲気に寄せすぎず、ブルー・グリーン・オレンジなども使ったカジュアルな色合いを試す。日記帳の表紙を並べ、紙のようにページをめくる見せ方を検討する。テーマや具体的な色は未確定。
- 一覧では自分の番や新着のある日記帳を上に表示し、状態ごとに見た目を変える。細かな順序や見た目は未決定。
- 初期フォントは普通の読みやすいものとし、将来の選択を検討。編集画面の UI は試作を見て決める。
- テンプレートの内容はユーザーが調べるため保留。アプリ名、アイコン、表紙デザインも未決定。

### 技術・法務

- Flutter、Supabase、Firebase Cloud Messaging の構成案で進める。契約・課金・実装・実機検証はまだ行っていない。詳細は [技術構成の提案](technology.md)。
- 電気通信事業法・個人情報保護の正式な対応は公開前に進める意向。保存・通報の設計に影響する点は設計段階から確認する。[法務・公開時の確認](legal-review.md)を参照。

## 優先して検討する事項

### 実装前に整理したいこと

- **周・順番の詳細**：次の周の順番を変更する UI、現在の周の並び替えが次の周に及ぼす影響、複数人による同時変更や例外時の処理を設計する。
- **招待リンク**：誰がリンクを作成できるか、発行時の注意表示・参加通知の具体的な UI、同時参加・失効時の処理を設計する。
- **下書き**：後勝ちによる上書きの注意表示、保存順の判定、オフライン・複数端末での編集と復帰時の挙動。注意表示は提案であり採用・内容は未決定。
- **ブロック・退出**：操作前の確認、解除・再参加、他のページに付けた退出者のリアクション、写真・下書き、削除同意待ちとの関係。
- **リアクション**：固定セットの具体的な種類、絵文字の入力・表示の詳細、取り消しの単位を決める。
- **初期版とアップデートの分割**：テンプレート・装飾・手書き・通知・検索の具体的な内容と数。編集画面、写真の詳細な制限、コメントの文字数上限。

### 公開前に決めること

- **バックアップと削除**：通常データ・写真・バックアップの対象と保持期間、削除完了までの期間、障害復旧時に削除を再反映する方法、利用者への説明。「利用者が元に戻せない」とバックアップ保管を混同しない。
- **通知のプライバシー**：日記本文・コメント・名前・日記帳名などを通知に含めるか、ロック画面への表示、設定の既定値と通知対象。本文を含めない案も検討する。
- **削除同意**：同意の集め方・有効期間・削除申請中に参加者が退出した場合の扱い。
- **安全・運用**：通報の対象と対応、ブロックと審査基準、アカウント削除、法務・個人情報保護、予算と問い合わせ対応。
- **技術検証**：署名 URL、写真を含むバックアップ、FCM の iOS 通知など。[チェックリスト](technology.md#検証事項)を参照。
