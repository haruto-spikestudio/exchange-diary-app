## フェーズ 1：ドキュメントと判断の整理

`decisions.md` の項目別整理と [用語集](glossary.md) は作成済み。残る作業は以下の判断と関連文書への反映。

| 論点 | 既に決まっていること | 判断候補・確認すること |
| --- | --- | --- |
| リアクション | 固定セットに加え、iPhone の絵文字キーボードから好きな絵文字を選べる方針。複数種類を付けられ、本人は取り消せる | 固定セットの種類、絵文字の入力・表示の詳細や取り消しの単位を決める |
| 周 | 開始時に対象者を決め、全員が書くかスキップすると完了。未担当者の退出・ブロックは対象から外す。その周の並び替えは未担当者同士、担当済みの人を含む変更は次の周に反映 | 順番変更の UI、現在の並び替えが次の周へ及ぼす影響、同時操作などの詳細を設計する |
| 招待 | 承認なし、24時間有効かつ参加１回限り。作成者が無効化・再発行でき、転送リスクの表示・参加通知・10人上限の確認を行う | 発行権限、注意表示・通知の UI と同時参加時の処理を設計する |

### 周のルールの例

以下は採用したルールを日記帳ごとの順番に当てはめた例。

- A → B → C の周で、A が書き B がスキップし C が書いたら周が完了する。
- 同じ周の途中で D が参加した場合、D はその周には加わらず、次の周の最後に入る。
- 同じ周で B が自分の番より前に退出・ブロックされた場合、残る A・C が担当を終えた時点で周を完了とする。現在の担当者が退出した場合は次の未完了者へ進み、残りがいなければ周を終えて次の周に進む。
- A が担当中に未完了の B・C を C → B に並べ替えた場合、A → C → B の順に担当し、B の完了時に周を終える。
- すでに担当を終えた人を含む順番変更は次の周に反映し、同じ周で二度担当させない。

## フェーズ 3：実機試作と判断

仮データを使い、参加者に説明しすぎず操作してもらい、課題・迷った箇所・本人の感想を記録する。人数・実施日・合否基準は未定。

| 確認したい体験 | 試す課題の例 | 記録すること |
| --- | --- | --- |
| 招待・参加・順番 | 招待から参加し、誰が次に書くか説明する | 迷った場所、参加前に過去ページの閲覧範囲を理解できたか、順番の説明 |
| スマートフォンでの編集 | フォームに書く、写真や装飾を配置する、手書きを試す | 操作の迷い、配置や手書きの扱いやすさ、楽しかった点と負担 |
| プレビュー・渡す・反応 | プレビュー後に渡し、別の参加者として読み反応する | 編集不可の理解、次の操作が分かるか、反応の付け方や取り消しの理解 |

観察結果を踏まえ、２形式の必要性とテンプレートの目標数（現在は８種類程度）を見直す。手書きや招待の体験は、画面だけのペーパープロトで確認できる範囲と実機で確認すべき範囲を分ける。

- 通報の受付・閲覧範囲・確認基準・停止・問い合わせまでの流れを検討する。通信の秘密や審査基準との整合性は未確認。
- ブロック時の影響確認、解除・再参加を決める。既存の削除方針と整合させる。
- 日記・コメント・招待・通知、共有範囲、保存先を整理し、所管の総合通信局等に電気通信事業法上の届出等を相談する。相談・届出は未実施。詳細は [法務・公開時の確認](legal-review.md)。
- 実際の取得情報や運用に合わせて利用規約とプライバシーポリシーのたたき台を作成し、公開前に確認する。
