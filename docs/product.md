# 企画・要件

## コンセプト

友人同士が、昔の交換日記の懐かしさをスマートフォンで手軽に楽しむ。日記を書くことに加え、ページをデザインする楽しさも大切にする。一般公開を目指す。

## 対象と体験

- 友人同士で使う。２人から最大10人までの日記帳を作成できる。利用者は日記帳を複数持てる。
- 日記帳を見られるのは参加者だけ。途中参加した人は、参加前のページも読める。
- 順番にページを書いて次の人に渡す。最初の順番は参加順。開始後は参加者なら誰でもいつでも次の番以降の順番を変更できるが、現在の担当者は変わらない。
- 書く期限は設けない。自分の番をスキップできるのは本人だけで、スキップした履歴を残す。
- 渡されたページには、参加者が固定の種類のリアクションや絵文字と短いコメントを付けられる。１人が複数種類のリアクションを付けられる。
- 自由配置型とフォーム型のテンプレートを両方用意し、書く人が選ぶ。テンプレートは全体で８種類程度を目指す。フォームの空欄は許す。
- 自由配置はできるだけ制限のない体験を目指す。手書きは Instagram ストーリーズのような操作感を参考にする。
- 写真は１ページ５枚まで。端末の写真アプリから選ぶ。
- 下書きは自動保存し、別の端末でも続きを書ける。見られるのは本人だけ。
- 渡す前にプレビューを表示し、渡した後は編集できないことを注釈で伝える。渡したページは書いた本人が削除でき、非表示機能は設けない。

## アカウント・招待・退出

- アカウントの作成方法は複数を組み合わせる。具体的な方法は未決定。
- 招待リンクで参加し、リンクの有効期限は24時間。
- 参加者はいつでも退出できる。他の参加者を日記帳から外す権限は設けない。
- 退出した人が書いたページとコメントは削除し、退出後は本人も日記帳を閲覧できない。退出者のページに付いた他の参加者のコメントとリアクションも削除する。退出者が他のページに付けたリアクションや写真の詳細な扱いは要設計。
- 日記帳の削除は参加者なら誰でも提案できるが、削除には参加者全員の同意が必要。未回答者がいる間は削除せず待ち、各参加者は削除が実行されるまで自分の同意を取り消せる。削除後は気が変わっても元に戻せない。同意の集め方などの詳細は未決定。
- コメントは編集できず、書いた本人だけが削除できる。

## 利用の流れ（設計案）

1. アカウントを作り、日記帳を作成する。
2. 有効期限24時間のリンクで友人を招待する。最初の順番は参加順。
3. 自分の番になったら、テンプレートを選んでページを作る。下書きは自動保存される。
4. プレビューを見て次の人に渡す。自分の番をスキップすることもできる。
5. 参加者が過去のページを読み、リアクションやコメントを付ける。
6. 参加者は順番の変更や途中参加・退出ができる。

例えば順番が A → B → C のとき、B が自分の番をスキップすると C の番になる。順番変更後も現在の担当者は変わらない。担当者の退出や途中参加のときの扱いは別途設計する。

## 通知・検索

- 自分の番、新しいページ、コメントなどの通知を用意し、種類ごとにオフにできるようにする。詳細な通知対象は要設計。
- 過去のページは時系列で見られるようにし、日付や書いた人から探せるようにしたい。

## 初期版

最初は iOS アプリを想定し、その後 Android アプリ、将来的にパソコン版も検討する。初期版に何を含めるかは未決定。[初期版・運用の提案](release-plan.md)に分割案を記載する。

## 非公開の基本方針

日記・写真・コメントなどは、その日記帳の参加者だけが見られる。下書きは本人だけ。アクセス制御や招待リンク保護などの実装方針は提案段階であり、[初期版・運用の提案](release-plan.md)で整理する。
