# 決定事項と検討事項

## 決定事項

2026-11-17、会話で確認。機能の希望と公開方針であり、初期版に全て含める決定ではない。

### これまでの決定

- 友人同士で使い、２人でもグループでも利用する。日記帳は複数作成できる。
- 日記帳は参加者だけが見られる。決まった順番で書き、期限は設けない。本人だけが自分の番をスキップできる。
- ページにリアクションと短いコメントを付けられる。
- 自由配置型とフォーム型のテンプレート、複数のデザインと装飾を用意する。
- 渡したページの編集は初期版に含めない。

### 今回の決定

- 一般公開を目指す。まず iOS アプリ、その後 Android、将来的にパソコン版も検討する。
- アカウント作成は複数の方法を組み合わせる。組み合わせの中身は未決定。
- 招待リンクは24時間有効。日記帳の参加者は最大10人。
- 最初の順番は参加順。開始後は参加者なら誰でもいつでも次の番以降の順番を変更できる。現在の担当者は変わらない。
- 途中参加を認め、途中参加者も以前のページを閲覧できる。
- テンプレートは全体で８種類程度を希望。フォームの空欄を許す。自由配置は制限のない体験を目指す。
- 手書きの操作は Instagram ストーリーズのような UI・UX を参考にする。
- 写真は１ページ５枚まで、端末の写真アプリから選ぶ。下書きは本人のみが見られ、自動保存し、別端末でも続けられる。
- 渡す前にプレビューを表示し、渡した後は編集できない旨を注釈で伝える。
- スキップした履歴を残す。スキップ時の下書きは削除する。確認画面の有無は未決定。
- 参加者はいつでも退出できる。ブロック時を除き他の参加者を外す権限は設けない。退出者が書いたページ・コメントは削除し、退出後は本人も閲覧できない。退出者のページに付いた他の参加者のコメントとリアクションも削除する。
- 日記帳の削除は誰でも提案でき、参加者全員の同意を必要とする。未回答者がいる間は削除せず待つ。各参加者は削除実行前なら自分の同意を取り消せる。削除後は元に戻せない。
- コメントは編集不可。削除できるのはコメントを書いた本人。
- リアクションは固定の種類を用意し、１人が複数種類を付けられる。iOS の絵文字のような絵文字も使えるようにしたい。固定の種類と絵文字の選び方は要設計。
- 通知は各種用意し、種類別にオフにできるようにする。過去ページは時系列に加え、日付や書いた人で探せるようにしたい。
- 渡したページは書いた本人が削除できる。非表示機能は設けない。公開後の編集を将来追加するかは未決定。

### 追加決定（2026-11-17）

- 上記の順番変更の範囲、退出者のページに付いたコメント・リアクションの削除、全員同意までの待機、削除前の同意取り消し、削除後に戻せない扱いを確認。現在の番を本人以外が飛ばさないため、順番変更は次の番以降に限る。

### 今回の追加決定・方向性

- Goodnotes のようなシンプルな画面に日記帳の表紙を並べ、パステル系のテーマを選べるようにしたい。日記は紙のようにページをめくる見せ方。
- 日記帳一覧では自分の番や新着のあるものを上に表示し、状態ごとにデザインを変える。詳細な順序や見た目は未決定。
- テキストが中心で、手書き・ステッカー・スタンプは補助の装飾。初期フォントは普通の読みやすいものとし、選択機能は将来的に検討。
- 編集画面の UI は試作を見て決める。テンプレートはユーザーが調べるため保留。アプリ名、アイコン、表紙デザインは未決定。
- Flutter の方向性で進める。その他の技術選定は提案に委ねるが、実装・導入や費用は未確定。
- 自分の番に退出した場合は次の人へ。途中参加者は次の周の最後に入り、その後は順番を変更できる。最後の１人の退出時は日記帳を自動削除する。
- スキップ時の下書きは削除。本人がページを削除すると、そのページのコメント・リアクションも削除。複数端末の下書きは後から保存した内容を優先する。
- 日記帳の削除待ち中に途中参加した人の同意も必要。退会等で参加者が減る場合の詳細は未決定。
- 一般公開時は最初は無料。運用費の上限は未定。問い合わせ対応は本人が担当する。
- 当初は通報・ブロックは不要との希望だったが、通報を受けて運営者がアカウントを停止する案を検討する方向に変更。通報内容の確認と停止は自動確定ではなく、具体的な基準・運用を検討する。利用者によるブロック時の扱いは後の決定を参照。審査適合性は未確認。

### 追加の方向性

- 初期テーマはパステルのピンク・ブルー・ラベンダーの３色で進める。具体的な色味は試作で決める。
- Flutter、Supabase、Firebase Cloud Messaging の提案をもとに進める。導入・契約・課金はまだしておらず、費用や実装方法は実際の構成を確認する。
- 通報を受け、運営者が確認して必要に応じアカウントを停止する案を検討。以前の「通報は不要」という希望から変更。審査条件を満たすかは未確認。
- 電気通信事業法・個人情報保護の正式な対応は公開前に進める意向。保存・通報の設計に影響する論点は設計段階から確認する。

### ブロックに関する追加決定

- 参加者が別の参加者をブロックすると、対象者をブロック操作をした日記帳から退出させる。以前の「他の参加者を外す権限は設けない」方針に、ブロック時の例外を設ける。
- その日記帳の中で、ブロックされた人が書いたページ・コメント・付けたリアクションを削除する。ページの削除に伴い、そのページに付いた他の人のコメント・リアクションも削除する。削除結果は日記帳の全参加者に反映され、他の日記帳は対象外。
- 対象者が現在の担当者なら、退出ルールどおり次の人に番を渡す。操作の確認方法、解除・再参加、写真・下書き、バックアップ等の扱いは未決定。

## 検討事項

- 初期版とアップデートの機能分割。提案は [初期版・運用の提案](release-plan.md) を参照。
- アカウント作成方法の組み合わせ、提案した技術構成の実装詳細と費用。
- 招待リンクの発行者、無効化、再利用、期限切れ時の扱い、参加上限到達時の扱い。
- 途中参加する際の周の境界、変更後の順番を次の周以降にどう反映するか。
- 退出した人の写真・他のページに付けたリアクション・下書きの扱い。
- 全員同意の集め方・有効期間・削除申請中に参加者が退出した場合、削除後のデータとバックアップ。
- ページ削除の確認方法と履歴、スキップの確認画面、端末間同期における保存順の判定とオフライン時の扱い。
- テンプレートと装飾の具体的な内容・数、手書きと自由配置の操作、写真の詳細な制限。
- コメントの文字数上限、リアクションに使う絵文字の範囲と取り消し、通知の種類・既定値。
- ブロック前の確認、解除・再参加、下書きと写真の詳細、削除同意待ちとの関係。個別ページ・日記帳・アカウントの削除ポリシー、アクセス制御、バックアップと通報への対応。

## 更新ルール

新しい判断は、決定日と理由が分かるよう記録し、関連する企画・デザイン文書にも反映する。過去の判断が変わった場合は、変更内容と理由が追えるように残す。提案は決定事項と区別する。
