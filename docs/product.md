# 企画・要件

## コンセプト

友人同士が、昔の交換日記の懐かしさをスマートフォンで手軽に楽しむ。テキストを中心に、手書き・ステッカー・スタンプなどでページを飾る楽しさも大切にする。一般公開を目指し、初期は無料で提供する。

## 対象と体験

- 友人同士で使う。２人から最大10人までの日記帳を作成できる。利用者は日記帳を複数持てる。
- 日記帳を見られるのは参加者だけ。途中参加した人は、参加前のページも読める。
- 順番にページを書いて次の人に渡す。最初の順番は参加順。参加者なら誰でも順番を変更できるが、現在の担当者は変わらない。その周は未担当者同士の順番を変更でき、担当済みの人を含む変更は次の周に反映する。途中参加者は次の周の最後に加わり、その後は順番を変更できる。
- 書く期限は設けない。自分の番をスキップできるのは本人だけで、スキップした履歴を残し、そのときの下書きは削除する。スキップもその周の担当を終えたものとして数える。次の人以外を指定して直接渡す機能は設けない。
- 渡されたページには、参加者が事前に用意された固定の種類のリアクションと短いコメントを付けられる。１人が複数種類のリアクションを付けられ、自分のリアクションを取り消せる。初期版では固定セットに加え、iPhone の絵文字キーボードから好きな絵文字も選べる方針。入力・表示の詳細や取り消しの単位は未決定。
- 自由配置型とフォーム型のテンプレートを両方用意し、書く人が選ぶ。テンプレートは全体で８種類程度を目指す。フォームの空欄は許す。
- 自由配置はできるだけ制限のない体験を目指す。手書きは Instagram ストーリーズのような操作感を参考にする。
- 写真は１ページ５枚まで。端末の写真アプリから選ぶ。
- 下書きは自動保存し、別の端末でも続きを書ける。見られるのは本人だけ。複数端末で編集した場合は後から保存された内容を優先するため、ほかの端末の編集内容が上書きされることがある。利用者への注意表示や具体的な保存順の判定は要設計。
- 渡す前にプレビューを表示し、渡した後は編集できないことを注釈で伝える。渡したページは書いた本人が削除でき、付いているコメントとリアクションも削除する。非表示機能は設けない。

## アカウント・招待・退出

- アカウントの作成方法は複数を組み合わせる。具体的な方法は未決定。
- 招待リンクは24時間有効で、参加が１回成立すると使用できなくなる。リンクの作成者は無効化・再発行できる。承認は不要で、転送先も参加し得る。発行時に転送先が参加・過去ページ閲覧できることを伝え、参加時は既存参加者に通知し、10人の上限を確認する。
- 参加者はいつでも退出できる。参加者による強制退出は、下記のブロックに伴う場合を除き設けない。現在の担当者が退出したら次の人に番を渡し、最後の１人が退出したら日記帳を自動削除する。
- 退出した人が書いたページとコメントは削除し、退出後は本人も日記帳を閲覧できない。退出者のページに付いた他の参加者のコメントとリアクションも削除する。退出者が他のページに付けたリアクションや写真の詳細な扱いは要設計。
- 日記帳の削除は参加者なら誰でも提案できるが、削除には参加者全員の同意が必要。未回答者がいる間は削除せず待ち、削除待ちの間に途中参加した人の同意も必要。各参加者は削除が実行されるまで自分の同意を取り消せる。削除後は気が変わっても元に戻せない。同意の集め方などの詳細は未決定。
- コメントは編集できず、書いた本人だけが削除できる。

## 利用の流れ（設計案）

1. アカウントを作り、日記帳を作成する。
2. 有効期限24時間・参加１回限りのリンクで友人を招待する。最初の順番は参加順。
3. 自分の番になったら、テンプレートを選んでページを作る。下書きは自動保存される。
4. プレビューを見て次の人に渡す。自分の番をスキップすることもできる。
5. 参加者が過去のページを読み、リアクションやコメントを付ける。
6. 参加者は順番の変更や途中参加・退出ができる。

周の開始時に対象者を決め、全員が書くかスキップすると周が完了する。未担当者が退出・ブロックされた場合は対象から外し、残る対象者が全員完了していれば周を終える。途中参加者は次の周から対象。詳しくは[用語集](glossary.md)を参照。

例えば順番が A → B → C のとき、A の担当中に未担当の B・C を C → B に変更できる。担当済みの人を含む変更は次の周に反映する。B が自分の番をスキップすると次の未担当者に進む。担当者が退出・ブロックされた場合も次の未担当者へ進み、残りがいなければ周を終えて次の周に進む。途中参加者は次の周の最後に加わる。

## 安全対策の方向性

参加者をブロックすると、その人はブロック操作をした日記帳から退出し、その日記帳内で本人が書いたページ・コメント・付けたリアクションを削除する。ページの削除に伴い、そのページに付いた他の参加者のコメント・リアクションも削除する。削除はその日記帳の参加者全員に反映され、他の日記帳は対象外とする。ブロック対象が現在の担当者なら、退出時と同様に次の人へ番を渡す。ブロックの解除・再参加、下書きや写真の詳細な扱いは未決定。

通報を受け、運営者が確認したうえで必要に応じてアカウントを停止する方法を検討する。通報の対象・手順・停止基準と、App Store 審査・法的要件との整合性は公開前に確認する。

## 通知・検索

- 自分の番、新しいページ、コメントなどの通知を用意し、種類ごとにオフにできるようにする。詳細な通知対象は要設計。
- 過去のページは時系列で見られるようにし、日付や書いた人から探せるようにしたい。

## 初期版

最初は iOS アプリを想定し、その後 Android アプリ、将来的にパソコン版も検討する。初期版に何を含めるかは未決定。[初期版・運用の提案](release-plan.md)に分割案を記載する。

## 非公開の基本方針

日記・写真・コメントなどは、その日記帳の参加者だけが見られる。下書きは本人だけ。アクセス制御や招待リンク保護などの実装方針は提案段階であり、[初期版・運用の提案](release-plan.md)で整理する。
