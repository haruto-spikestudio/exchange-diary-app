# 法務・公開時の確認

2026-11-17 に日本での一般公開を想定して公式情報を調査した初期整理。対象年齢、配信地域、具体的な機能・提供方法、データの保存先が未確定のため、法的な適用・届出要否・審査通過は未確定。法的助言や完成した利用規約ではない。公開前に最新情報を再確認し、必要に応じ所管窓口や法律の専門家へ確認する。アプリは未実装。

## 1. 電気通信事業法と通信の秘密

- 日記・コメントを特定の参加者間で共有する機能があるため、サービスの仕組みが「他人の通信を媒介する」電気通信事業に該当するか、届出や他の義務が必要かを公開前に確認する。**無料・個人運営・非公開グループであることだけで結論は出せない。** 機能や提供形態ごとに個別に判断する。[政府のサイバーセキュリティ関係法令 Q&A：Q35・Q36](https://security-portal.cyber.go.jp/guidance/law-handbook/v2-07.html)
- 必要な届出に該当する場合、[e-Gov の案内](https://shinsei.e-gov.go.jp/recept/procedure/lists/procedureInformation?gtaTetCd=145181GA00001)では事業開始前の提出、手数料なしとされる。ただし本アプリが届出対象かは確認できていない。
- 電気通信事業者に該当する場合の通信の秘密や、運営者による日記・コメントの確認、外部サービスへの送信の扱いも検討する。Apple のフィルタリング等の要件との両立は、通信の秘密への影響を含めて個別に確認し、運営者が自由に本文を閲覧・自動分析できる前提にしない。
- 正式な届出・規約等の対応は公開前に行う予定。ただし通信の内容を確認する通報対応やデータ保存の設計に影響し得るため、実装の早い段階で日記・コメント・招待・通知の流れ、保存先、利用者間で共有される範囲、無料であることを整理し、所管の総合通信局等に届出要否と必要な対応を確認することを推奨する。実際の相談や届出はまだ行っていない。

## 2. 個人情報保護

- 個人情報に当たる情報や取得・利用目的、保存期間、クラウド事業者、国外での取扱い、削除・開示等の窓口を整理する。日記や写真に本人や第三者の個人情報が含まれる可能性がある。
- 利用目的の通知・公表、アクセス制御、委託先の管理、適用される開示・削除等への対応を確認する。小規模な運営でもリスクに応じた安全管理措置が必要：[個人情報保護委員会のガイドライン](https://www.ppc.go.jp/personalinfo/legal/guidelines_tsusoku/)。
- 漏えい時は対象事案に応じて、所管当局への報告と本人通知が必要になる場合がある。対象や連絡先は事案・所管により確認する：[個人情報保護委員会の案内](https://www.ppc.go.jp/personalinfo/legal/leakAction/)。
- 解析 SDK や通知サービスを使う場合は送信先・送信情報・目的を洗い出し、外部送信規律の適用を個別に確認する。[政府の Q&A](https://security-portal.cyber.go.jp/guidance/law-handbook/v2-07.html)参照。

## 3. 利用規約・プライバシーポリシー

- 利用規約のたたき台には、参加・招待、権利侵害の禁止、投稿の扱い、退出時の削除、日記帳の全員同意削除、サービス停止、問い合わせ等を検討する。規約を用意することと法令・審査への適合は別問題。
- プライバシーポリシーには、実際の取得項目、利用目的、委託先や外部送信、保存・削除、問い合わせ等を実装に合わせて記載する。Apple はアプリ内と App Store Connect の両方にプライバシーポリシーへのリンクを求める。[App Review Guidelines 5.1](https://developer.apple.com/app-store/review/guidelines/)
- 自分で文案を用意することはできるが、サービスとデータ取扱いを具体化した後、公開前に法的確認を受けることを推奨する。現時点で文書作成・法律相談は行っていない。

## 4. App Store 審査：通報・ブロック

- 当初はクローズドなため通報・ブロックは不要という希望だったが、通報を受けて運営者が確認し、必要に応じアカウントを停止する案を検討する方向に変更。通報だけで自動的に停止する仕様は決まっていない。
- 一方、Apple の [App Review Guidelines 1.2](https://developer.apple.com/app-store/review/guidelines/) はユーザーが内容を作成・共有するアプリに対し、不適切な内容をフィルタリングする方法、通報と対応、悪質な利用者のブロック、連絡先の公開を挙げている。法律上の義務と Apple の審査基準は区別する。
- 非公開グループだから例外になることや、通報と運営者によるアカウント停止だけで、利用者によるブロックの条件を満たすことは確認できていない。フィルタリングと連絡先も含め、具体的な対応と審査結果は未確定。利用者による強制退出を認めない方針、プライバシー・通信の秘密と両立する方式を検討し、必要に応じ Apple に確認する。
- アカウント作成機能があるアプリは、アプリ内でのアカウント削除を提供する必要がある：[Apple の案内](https://developer.apple.com/support/offering-account-deletion-in-your-app/)。

## 5. その他の公開前確認

- 年齢対象や未成年者への対応、公開地域、投稿写真・スタンプ・フォントの権利、アプリ名・アイコンの権利を確認する。
- 最初は無料。将来、課金や有料コンテンツを提供する場合は、その販売方法に応じて特定商取引法の表示や App Store の決済ルール等を再確認する。[消費者庁：通信販売広告 Q&A](https://www.no-trouble.caa.go.jp/qa/advertising.html)
